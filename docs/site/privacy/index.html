Rusty's Canvaz – CAN Analyzer

Privacy policy

Last updated: 6 November 2026

This policy describes how Rusty's Canvaz – CAN Analyzer, developed by Christoffer Zakrisson (rustypig91), handles information. It also covers this policy page.

Canvaz processes CAN traffic and DBC files on your computer. The app does not upload your CAN traffic, recordings, projects, DBC files, or diagnostic logs to the developer. It includes no advertising, usage analytics, or automatic crash-report uploads. No Canvaz account is required.

Data the app uses

  • CAN communication: Canvaz receives frames from the interfaces you select and decodes them locally. This includes frame identifiers, payload bytes, timestamps, channel information, and decoded signal values, including J1939 information where enabled. When you start transmission or simulation, the app sends the configured frames to the selected CAN interface. Traffic may contain personal, vehicle, or other sensitive information.
  • Devices and configuration: Interface names, backend types, channel assignments, bitrates, protocol settings, and user-chosen channel names are used to connect to devices and restore your workspace.
  • Files and saved work: The app reads the DBC and project files you select. Projects and automatic session saves contain channel settings, DBC file paths, plots, filters, and simulation settings, including configured signal values and raw frame payloads. Preferences and the last project path are also saved locally.
  • Recordings and exports: Choosing Data → Log to disk… saves incoming and transmitted CAN frames to the CSV file you select. Recording is independent of display filters, pausing the view, and the in-memory retention window. CSV and plot-image exports are written to destinations you choose.
  • Diagnostics: The local message log and console output can contain the app version, device names, file paths, and error details. The System resources dialog reads process names and identifiers, CPU usage, and memory use to display Canvaz's resource consumption. This information is not automatically sent to the developer.

Storage, retention, and deletion

Live trace and plot data are held in memory, subject to the selected retention window and display limits. Automatic session saving preserves workspace configuration, not a recording of received traffic. Simulation payloads can be saved as part of that configuration.

Preferences and session files are stored in Canvaz's application-data folder in your user profile. Direct-download builds normally use %APPDATA%\com.christoffer.canvaz on Windows and $XDG_DATA_HOME/com.christoffer.canvaz on Linux (defaulting to ~/.local/share/com.christoffer.canvaz). The Microsoft Store edition uses the separate identifier com.christoffer.canvaz.store for its data folders and embedded webview profile. It does not automatically import direct-download preferences or sessions. Windows may redirect packaged data locations within per-user package storage. The embedded webview may also keep a local runtime profile or cache.

Saved projects, recordings, and exports have no automatic expiry date. Clearing the trace or changing its retention window does not delete those files or stop an active recording. To remove stored data, stop recording, close Canvaz, and delete its application-data files and any projects, recordings, exports, and backups you no longer need. Remove webview profile data separately where applicable. Uninstallation may leave files behind; it should not be relied on to preserve or remove your data.

Canvaz does not add encryption to local files or CAN communication. Access is governed by your operating system and filesystem permissions. Synced folders, backups, connected devices, and other bus participants may retain copies outside Canvaz's control. Deleting a file is not secure erasure. The developer cannot access or delete data held only on your computer.

Network access and third-party services

Microsoft Store edition: Canvaz does not use the GitHub updater in this edition. It does not check GitHub for newer releases or download or install GitHub updates, including when preferences have been copied from a direct-download installation. Microsoft Store and Windows manage Store updates. Choosing Open Microsoft Store opens the Store's Updates and downloads page; it does not ask Canvaz to install an update or restart.

The Store edition includes a fixed version of the WebView2 runtime. Updates to that bundled runtime are delivered with Canvaz's Store packages rather than through the runtime's own automatic updater.

GitHub updates: Direct-download release builds check GitHub for a newer release at startup. About → Check for Updates also contacts GitHub. Skipping a release hides its startup notice but does not disable later checks. Choosing an update downloads release metadata and installation files from GitHub and its download infrastructure. These requests expose your IP address and ordinary request details, such as the requested release and HTTP headers, to those services. They do not include CAN traffic, device configuration, DBC files, projects, recordings, or local logs. See the GitHub Privacy Statement.

Platform services: Windows and the Microsoft Edge WebView2 runtime used to display Canvaz on Windows may perform their own update and diagnostic processing according to your system settings. If you obtain Canvaz through Microsoft Store, Microsoft also processes Store distribution, installation, and update information under the Microsoft Privacy Statement. Operating-system, runtime, and driver services operate independently of Canvaz's local data handling.

Opening project, support, donation, or other external links uses your browser or the corresponding system app. Information you provide to those services is handled under their policies. CAN frames are sent to the interface and bus you select; further processing by connected equipment is outside Canvaz's control.

Information you choose to share

If you email the developer or submit an issue, the developer receives the contact information, message, and attachments you provide and uses them to respond and investigate the report. Support correspondence may be retained while needed to resolve and follow up on the request. You can request deletion of correspondence held by the developer using the contact address below, subject to applicable legal obligations.

GitHub issues are public. Remove personal information, credentials, confidential DBC definitions, and sensitive CAN data before sharing files or logs. Canvaz does not sell personal information or share local app data with advertisers.
